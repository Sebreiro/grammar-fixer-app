# Requirements: Hotkey Grammar Corrector — Ledger Hardening

**Defined:** 2026-08-30
**Core Value:** The daemon corrects text reliably on both display servers and never loses, corrupts, or leaks the user's text

## Provenance

Every requirement below is one entry from the BMAD deferred-work ledger at
`_bmad-output/implementation-artifacts/deferred-work.md`. Nothing here was invented.

At intake the ledger held **229 entries** in two formats — 121 canonical `### DW-n:` headings
that `bmad-loop sweep` parses, and 108 flat `- source_spec:` entries appended by dev sessions
and never normalized, which the orchestrator counts as zero. By status: 89 open, 74 parked,
66 done. Intake scoped the **89 open** entries. Of those, 88 became v1 requirements and
**38 were subsequently removed** as test-shaped work — see *Removed: Test-Shaped Work*. The
milestone now scopes **50** requirements; parked, done and removed are all out of scope
(see PROJECT.md).

Flat entries have no canonical id, so they are addressed here as `FLAT-nn`, numbered by their
order of appearance in the ledger. The `Ledger` column carries the id and — for flat entries —
the source spec that filed it, so every requirement is traceable back to its origin bullet.

## Verification

Each open entry was checked against the current code before it became a requirement, because
ledger status is hand-maintained and 66 entries were already closed without the file always
saying so. Results:

- **1 entry verified already fixed** and dropped from scope — see *Verified Already Resolved*.
- **3 entries could not be confirmed** — DW-46, FLAT-30 and FLAT-32 describe load-sensitive
  cross-suite flakes that three consecutive idle runs (946 passed / 2 skipped each) could not
  reproduce. All three were test-shaped and have since been removed from scope.
- **85 entries confirmed still open** against the code, of which 50 remain in scope.

Confirmations were made by reading the cited code, not by trusting the entry. Some examples:
`provider_registry.dart` holds exactly one factory (DW-115); `wayland_portal_global_hotkey.dart`
returns `effective: null` at all three construction sites (DW-66); `main.dart` sets only
`setTitle`, `setSkipTaskbar` and `setPreventClose` on the toplevel (DW-50); `global_hotkey.dart`
declares `bindingChanges` with no synchronous accessor (FLAT-02).

One surviving entry — PANEL-09 (FLAT-42), the checklist-step renumbering ban — cannot be
falsified by reading code. It is open by construction until someone performs and records the
observation. The other entries of that kind were test-shaped and have been removed.

### Parked Ledger Entries (74)

The 74 entries carrying `status: parked` — deliberately filed and not scheduled. The cluster
with real user impact, should it be promoted:

- **DW-100**: a corrupt or truncated `history.sqlite` has no recovery path and the daemon cannot repair itself
- **DW-101**: schema v1 ships with no committed `drift_schemas/` snapshot and no `onUpgrade` branch
- **DW-104**: history growth is unbounded and unclearable, and every row holds the user's plaintext
- **DW-105**: `corrections_created_at_idx` does not cover `recent()`'s `(created_at DESC, id DESC)` tie-break
- **DW-106**: `history.sqlite` is created at the process umask, so every local account can read the plaintext
- **DW-110**: no code owns `AppDatabase`'s lifecycle, so a daemon that forgets `close()` never exits
- **DW-111**: `SqliteException` escapes `DriftCorrectionRepository` as a vendor type across the port boundary
- **DW-113**: `AppDatabase`'s public constructor is the unguarded door back to a synchronous `NativeDatabase`

Un-park a single entry by changing its `status:` line back to `open`; the whole set with:

  _bmad-output/implementation-artifacts/deferred-work.md
