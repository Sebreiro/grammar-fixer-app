<objective>
Let the cause decide.

Purpose: this is the blocker in 01-VERIFICATION.md — the phase goal's first clause, failed.
`x11_global_hotkey.dart:213` computes `final refusal = _refusalOf(error)` and then never reads
its code; the arm branches only on whether `_effective != null`. For `keyRefused` and
`badRequest` that is correct and is a real strength of the acquire-before-release design the
registrar acquired in plan 01-03. For `workerGone` it is false: the worker that owned the
previous grab is gone, so the previous combination is either dropped by the X server or
held-but-deaf — the X socket the dead isolate opened has no finalizer, so the server keeps
swallowing the combination system-wide while nobody reads that connection's event queue — and
the daemon answers `HotkeyBound(effective: <previous>, authority: application)`. The settings
screen renders "In effect: …" with no failure notice, for a grab nothing is serving, while the
combination is taken from every other application on the desktop.

This is the same failure class HOTKEY-01 was raised to close — a discarded result reported as
success — reappearing one layer up, which is why it is adjudicated against the goal rather
than waved through as a code-quality nit. And the distinction the whole `HotkeyRefusalCode`
enum exists to carry is thrown away precisely where it changes the answer.

**Say it plainly: this is a PLANNING gap, not an executor failure.** Plan 01-03's must-have
truth reads *"`HotkeyUnavailable` is returned from the X11 bind path only when nothing is held
— when a previous combination is still in effect, a refused rebind returns `HotkeyBound`
naming that previous combination"*. 01-03's executor implemented that truth exactly as
written, and 01-VERIFICATION.md verified it as written. The truth was wrong: it states
unconditionally what is only true while the backend is still there. The unconditional wording
is what licensed the branch. The amended truth is in this plan's `must_haves.truths`, and
plan 01-20 files the amendment in the append-only ledger — 01-03-PLAN.md itself is executed
and is not rewritten.

Output: one arm in one infrastructure adapter that reads the code it already computes, 01-15's
red row green, and the three contrast rows still green.

**The one arm that changes.** `X11GlobalHotkey._bind`'s `on Object catch` for a grab the seam
rejected, `x11_global_hotkey.dart:205-235`. Its current shape, in order: the `_disposed` check
(`_shutDownDuringBind`), then `final refusal = _refusalOf(error);`, then
`final stillInEffect = _effective;`, then `if (stillInEffect == null) { log; return

**What must NOT move.** The `_disposed` check stays first — its long comment explains that the
shipped seam *rejects* a grab that lands during teardown, so that is the branch the
stop-during-rebind race actually takes, and reordering it would tell the user this session
refused the shortcut for something the daemon itself did.
