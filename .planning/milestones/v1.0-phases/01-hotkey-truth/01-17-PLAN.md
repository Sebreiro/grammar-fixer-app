<objective>
Kill the worker for real and read the screen.

Purpose: 01-VERIFICATION.md is explicit about the evidence tier of this gap — *"this is code
inspection plus a zero-coverage finding, NOT an observed runtime failure. Nobody killed the
worker mid-grab and watched the screen."* — and equally explicit about what closure owes:
*"the closure plan should include the observation, not just the patch."* Plans 01-15 and 01-16
are the oracle and the patch. This is the observation.

It matters beyond ceremony. The chain has four seams between the isolate's death and the
rendered sentence — `Isolate.spawn`'s `onError`/`onExit` port, `_failPending`, `_refusalFor`,
and the adapter's catch arm — and a binding-free suite drives only the last of them. A fake
registrar that rejects with a hand-built `HotkeyRegistrarRefusal(workerGone)` proves the arm
reads the code. It does not prove that a real dead isolate *produces* that code, that the
reply reaches a caller at all rather than hanging (CR-01 says the next `grab()` never
completes and `SettingsController._mutating` latches), or that the screen renders what the
value says. Only a run does.

**One thing is contrived and it is named.** Nothing outside the process can kill this daemon's
worker isolate on demand: `handle` has no `on Object` guard and `Isolate.spawn` defaults to
`errorsAreFatal: true`, so a Dart throw on the grab path is fatal to the worker — but every
throw the worker can actually take is already guarded into a modelled refusal
(`_openBindings` catches `DynamicLibrary.open` and the whole `_X11Bindings` construction;
`_openDisplay` reads a null pointer as a value). That is a genuine finding in its own right and
the record states it: **the arm is reachable in production and unreachable from outside the
process.** So the worker death is injected, in a throwaway git worktree that never touches the
developer's tree, and everything downstream of the injection is the shipped chain.

Output: `tool/uat/worker_gone_probe.sh`, a before/after pair of recorded runs, a screenshot of
the real settings screen, and `test/platform/worker-gone-observation.md`.

**How the settings screen is reached in this container, from UAT test 1.** There is no
StatusNotifier host here — snixembed, stalonetray, trayer, tint2, xfce4-panel, waybar,
plasmashell and gnome-shell are all absent — so the tray is not the route. The panel is raised
by AD-14's second launch: running the bundle again while one is resident prints *"another
instance is running; asked it to show its panel"* and exits 0. Settings is then opened with the
panel's gear (`daemon_home.dart:223`).

**How a rebind is driven, from UAT test 3.** The combination is captured into the settings
field by pressing it (`xdotool key --clearmodifiers ctrl+shift+<key>`), then Apply is pressed.
UAT test 3's ordering note applies here too and is why the sequence is the realistic one: a
held passive grab also steals the keypress from the capture field.

**The injection point, and why it is the one to use.** `_X11Worker._grab`
(`x11_key_grab_registrar.dart:706`) receives `keysymName` already validated by `handle`
(`:676-703`), and `handle` carries no `on Object` guard. A throw at the top of `_grab`,
conditional on a marker key, is therefore fatal to the worker at exactly the moment a reply is
pending: `_ask` (`:359-370`) registers `_pending[id]` **before** `commands.send(...)`, so the
in-flight completer is there to be completed by `_failPending` when `onError` arrives. Key the
injection on **`F9`**, which is in `HotkeyKeyCatalogue`'s F1–F12 run, so that:

- the startup bind of `Ctrl+Shift+G` (keysym `g`) succeeds and `_effective` is genuinely set, and
- the rebind to `Ctrl+Shift+F9` is the one press that kills the worker.

`Ctrl+Shift+F9` carries two modifiers, so D-13's at-least-one-modifier rule is satisfied and
the capture field accepts it.

**The two revisions to run at, and what each must read.**

| Run | Revision | Expected daemon log for the Apply | Expected screen |
|---|---|---|---|
| pre-fix | the parent of 01-16's `lib/` commit | `refusal_code":"workerGone"` **and** a message containing `abandoned` | "In effect: Ctrl+Shift+G" — the false report |
| post-fix | 01-16's commit (or HEAD) | `refusal_code":"workerGone"` **and** the message `the X11 key grab was refused` with no abandonment clause | the `noBackend` cause line followed by the registrar's own sentence, *"the X11 hotkey worker stopped before answering, so no global shortcut is registered — the tray menu still opens the panel"* |

The log half is fully greppable, which is what makes the before/after gate mechanical rather
than a reading. The screen half is the part a human — or the executor reading the captured PNG
— confirms.

**The result-line format**, modelled on `panel_toggle_probe.sh`'s `ROUTE …` line so both
probes read alike and a grep on one does not silently match the other:

`RESULT rebind-worker-gone REV=<sha> INJECTED=yes BOUND=<combination> REQUESTED=<combination> REFUSAL_CODE=<code> LOG=<abandoned|refused|none> SCREEN=<png path> VERDICT=<REPORTED_IN_EFFECT|REPORTED_UNAVAILABLE|UNCLASSIFIED>`

Fields separated by exactly one space, in the order shown. The gates below match on adjacent
field pairs, so a reordered or extra-separated field fails them.

Structure, in this order.

1. **Preflight.** Assert `DISPLAY` (default `:99`) answers; assert `xdotool`, `xwininfo`,
   `xprop`, `scrot` (or `import`), `dbus-run-session`, `git` and the Flutter SDK are reachable,
   exporting the PATH from `<interfaces>` first; assert `git status --porcelain -uno -- lib/
   test/ tool/` prints **nothing** and refuse to run otherwise. Every miss is a halt with a
   named reason on stderr and a non-zero exit — never a verdict.

   Scope that gate exactly as written, and do **not** widen it back to a bare `git status
   --porcelain`. Measured in this repository the bare form returns **87 lines** — two tracked
   `.planning/` modifications and 85 untracked files under `.claude/` — none of which a
   detached-worktree build can reach, so the bare form never opens and the probe would halt at
   preflight on every invocation. The scoped form keeps the entire safety property this plan
   argues for: the injection is an edit to a **tracked** file under `lib/`, so a tracked
   modification in the source trees is exactly the signal worth refusing on, and
   `git status --porcelain -uno -- lib/ test/ tool/` is measured empty here. Untracked files
   are excluded deliberately and for a second reason as well — this plan's own
   `tool/uat/worker_gone_probe.sh` is untracked the first time it runs itself, and a gate that
   refused on that would refuse on its own existence.
2. **A throwaway worktree, never the developer's tree.** `git worktree add --detach
   "$WORKTREE" "$REV"` into a temp root created as `mktemp -d -t worker-gone-probe.XXXXXXXX`,
   so the worktree's path carries the literal token `worker-gone-probe.` and step 10's leak
   check can name the probe's **own** root instead of counting worktrees globally. Everything
   from here to step 7 happens inside it. This is the single most important property of the
   script: the injection is a source edit, and a source edit in the working tree is how an
   uncommitted patch gets destroyed. Do **not** patch in place and do **not** reach for
   `git checkout --` or `git stash` to undo anything.
3. **Inject the fault, in the worktree only.** At the top of `_X11Worker._grab` in
   `<worktree>/lib/src/infrastructure/hotkey/x11_key_grab_registrar.dart`, insert a guard that
   throws a `StateError` when `keysymName` equals `F9`, with a message that names itself as the
   probe's injection so it is unmistakable in any stack trace. Echo the resulting `git diff`
   from inside the worktree to stdout, indented under the result line, so the record carries
   the exact contrivance rather than a description of it. Assert the diff is **one hunk in one
   file** and halt if it is not.
4. **Build the bundle in the worktree** and assert the produced binary's mtime is newer than
   the worktree's creation, so a stale artefact cannot be mistaken for a fresh one. A cold
   Flutter Linux release build in a fresh worktree takes several minutes; that is expected, not
   a hang — print a progress line before it so a reader does not kill it.
5. **Seed the config and start the daemon** in a per-run XDG tree derived from `mktemp -d`,
   exactly as `panel_toggle_probe.sh` does, with `Ctrl+Shift+G` as the bound combination. Wait
   for the toplevel to exist rather than sleeping a fixed time: poll up to 30 s, then halt.
   Resolve the toplevel by `WM_CLASS` plus `_NET_WM_PID`, require exactly one survivor, and
   echo the chosen id.
6. **Confirm the starting state before contriving anything.** The daemon must actually hold the
   grab: fire `Ctrl+Shift+G` once and require the panel to map. A run that observes nothing must
   never be mistaken for a working daemon — this is the same rule
   `panel_toggle_probe.sh`'s warm-up step enforces, and it is what makes `BOUND=` in the result
   line a measurement rather than a restatement of the config file.
7. **Drive the rebind.** Raise the panel (AD-14's second launch), open settings with the gear,
   arm the capture field, press `Ctrl+Shift+F9`, confirm the field shows the captured
   combination before pressing Apply, then press Apply. Every GUI step is confirmed or is a
   named halt — never a blind sleep followed by an assumption. A step that cannot be confirmed
   halts with the step name, the window id, and the screenshot taken at that moment.
8. **Read both surfaces.** Grep the daemon log for the line the Apply produced and extract

   screenshot of the settings screen to the path named in the result line.
9. **Emit the result line** in the `<interfaces>` format, followed by the daemon log lines for

   `abandoned` ⇒ `REPORTED_IN_EFFECT`, `refused` ⇒ `REPORTED_UNAVAILABLE`, anything else ⇒
   `UNCLASSIFIED` with the raw lines printed. The screen is recorded, not classified — an OCR
   verdict would be a second oracle with a second failure mode, and the record's whole point is
   that a human reads the sentence.
10. **Clean up on every path, including halts**, via a `trap … EXIT`: stop the daemon by the

    fails, print a loud, unmissable line naming exactly what is left behind and where — a probe
    that leaks a patched worktree is worse than a probe that does not run.

Add no tolerance, no retry and no "if it looks like it refused, call it refused" smoothing. The
value of this file is that it reports what happened.
