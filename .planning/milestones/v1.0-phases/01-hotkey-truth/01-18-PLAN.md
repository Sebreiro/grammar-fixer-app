Close the two warnings 01-VERIFICATION.md raised on the G-01-13 fix's own new code. Neither

**WR-03 — the one witness call with no AD-15 guard.** The read side is guarded:
`_keyboardStillHere()` wraps `focusUnmoved` in `on Object catch`, logs by type, and answers
`false` (`window_manager_panel_visibility.dart:1068-1081`). The write side is not — the `focus`
arm calls `_witness.recordFocusGained()` bare (`:895-898`). The port documents only `dispose()`
as never throwing; `recordFocusGained` carries no such promise, and the X11 implementation
reaches `DynamicLibrary.open`, `calloc` and an FFI call behind it. A throw escapes the
`_window.events` **listener callback** — where the subscription's `onError` cannot see it, since
that handles stream errors and not listener throws — and lands in the root zone at
`main.dart:735`. Behaviourally benign today (a failed record leaves nothing witnessed, so
`focusUnmoved` answers `false` and CAP-14 dismisses as before), but it breaks the file's own
guard symmetry, and the fake has `readError` for `focusUnmoved` and nothing equivalent for the
write side — so the asymmetry is pinned by nothing.

**WR-04 — a display with no out-parameters.** `_open` assigns `_bindings` and `_display`
*before* allocating the two out-parameters (`x11_keyboard_focus_witness.dart:155-186`). If
either `calloc` throws, `_open` has already published a state every later call treats as
healthy — `_bindings != null && _display != nullptr` returns `existing` — and `_readFocus` then
executes `_focusOut.value = _none` on a null pointer. That is a SIGSEGV no `on Object catch` can
reduce, in a file whose whole design premise is that a fault on this path must not be reachable.
Very low likelihood, since it needs an allocation failure. The cost is the process. The fix is
ordering.

Output: symmetry on the write side, ordering on the open side, and the injection point that
keeps both pinned.
</objective>

**1. The guard, in the adapter.** Replace the bare `_witness.recordFocusGained();` in the
`focus` arm with a call to a new private method `_recordFocusWitness()`, declared beside
`_keyboardStillHere()` so the two halves of the seam's backstop sit together. Its body is the
same shape as `_keyboardStillHere`'s: `try { _witness.recordFocusGained(); } on Object catch

the caller's behaviour is identical whether the recording happened or not.
