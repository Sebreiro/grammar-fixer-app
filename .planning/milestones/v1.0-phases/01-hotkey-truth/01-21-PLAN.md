Two changes; 01-REVIEW.md CR-02 states outright that neither alone is sufficient, and
01-VERIFICATION.md lists them as separate `missing:` items.

**A. The output directory is restricted the moment it exists.** Immediately after the
`mkdir -p "$OUT_DIR"` at `:225`, add `chmod 700 "$OUT_DIR" || die "could not restrict $OUT_DIR"`.
A halting failure, not a best-effort: the whole point is that the directory is never readable
by another account, and a `chmod` that silently failed would leave it exactly as it is today.
Use `die` rather than `halt` because this is inside `preflight` and `die`'s exit code is the
preflight one. This is the same treatment `$XDG_ROOT/rt` already gets eight lines into
`start_daemon`, which is what makes the omission an oversight rather than a considered
exemption — say that in the comment above the new line.

Note and do not "fix" one adjacent thing: `halt`'s screenshot path at `:80` falls back to `/tmp`
when the output directory variable is empty. That fallback is unreachable, because `halt` only
takes a screenshot when a toplevel window id has been resolved, and the resolution step runs
after `preflight` has already assigned the output directory. Leave it, and record the reasoning
in the SUMMARY rather than widening this task.

**B. The panel the run raises cannot be carrying the user's text.** The clipboard is what seeds
the panel editor on show, so the precondition is established at the clipboard, before anything
maps a panel. Add a gate to `preflight`, positioned immediately after the required-tool loop at
`:186-189` and before the dirty-tree gate, that does three things in order:

1. Add `xclip` to that required-tool loop's list, so a missing tool is a named halt rather than
   a silent skip of the whole gate.
2. Read the clipboard selection of `$DISPLAY`. An unowned selection makes the reader exit
   non-zero with no output; treat that as empty, which is the ordinary case on a throwaway
   `Xvfb` display. A non-empty read is a `die` naming the situation: this probe raises a panel
   that is seeded from the clipboard and photographs it, so it will not run while the clipboard
   holds anything, and the operator should clear it or use a display the probe can have to
   itself.
3. Only once the read proved empty, clear the selection explicitly so the precondition is
   established rather than merely observed. Record the pid of the process that then owns the
   empty selection in a new per-run global declared beside the others at `:51-66`, and add a
   guarded teardown for it to `cleanup` — guarded in exactly the discipline Task 1 just
   established, so a run that never set the pid signals nothing.

The refusal is the load-bearing half and the reason this is not simply "clear the clipboard":
clearing a clipboard the probe did not fill would destroy the user's text, which is the very
clause this gap is adjudicated against, and it is the same class of defect as Task 1's
unanchored signal. Refuse first, then establish. Put that reasoning in the comment above the
gate, in one sentence.

**C. The four directories already on this disk are restricted, not deleted.** A and B close the
mechanism for future runs. They do nothing about the runs that already happened: measured on this
host right now, `/tmp/worker-gone-probe-out/` holds four output directories from the 11 September
runs, every one `drwxr-xr-x` with every file `-rw-r--r--`, including
`post-fix-2-49c5f9f-20260911062625/step-settings-gear-before.png` — the exact file
01-VERIFICATION.md opened and described as "a capture of the 'Your text' editor with the three
suggestion cards beneath it". Leaving them is leaving the Core Value clause violated on disk after
a plan whose whole purpose is that clause.

Restrict them, in one command, and do not delete anything:

`find /tmp/worker-gone-probe-out -mindepth 1 -maxdepth 1 -type d -exec chmod 700 {} +`

Three properties of that command are the reason it is written this way rather than any other way,
and the SUMMARY records them:

- **It restricts rather than deletes.** Two of these four directories are cited as evidence in
  01-VERIFICATION.md by full path — `pre-fix-4247446-20260911062323/settings-after-rebind.png` is
  the pre-fix half of the proof-by-difference, and `post-fix-2-49c5f9f-20260911062625/` is the
  post-fix half. Deleting them would destroy the record's own proof. A 0700 directory is
  unreachable by another local account while remaining readable by its owner, which is exactly the
  protection A installs for future runs — the same mechanism applied to the same exposure.
- **It is anchored and bounded.** An absolute path, `-mindepth 1 -maxdepth 1` so only the immediate
  run directories are touched, `-type d` so it cannot wander, and `-exec chmod` with no `rm`
  anywhere. A blind `rm -rf` on a `/tmp` glob would be the same class of defect as the unanchored
  `pkill` Task 1 exists to remove, in a plan that would then be closing one instance of a rule while
  breaking another.
- **It is a one-time operator remediation, NOT a change to the script.** Do not teach
  `worker_gone_probe.sh` to chmod directories from earlier runs. This plan's second prohibition says
  the probe never mutates state it did not create, and a run reaching back into its predecessors'
  output would violate it — the same prohibition that made B a refusal instead of a clear. The
  script owns the directory it creates; the operator owns the ones already there.

If `PROBE_OUT_DIR` was ever set to something other than `/tmp` on this host, apply the same command
under that root too and name it in the SUMMARY. The parent `/tmp/worker-gone-probe-out` itself stays
world-traversable, consistent with T-01-137's accepted disposition: only labels and timestamps are
visible through it, and no capture, log or diff is reachable once every leaf is 0700.

What this task deliberately does NOT do, and the SUMMARY must say so with the reason: it does

panel it shows carries no user text — and with the directory at 0700 no other account can read
it either way. State that trade in the SUMMARY as a trade, not as a clean removal of the
capture.
