<objective>
Stop `HotkeyBinding.modifiers` being a caller-supplied mutable set held by reference behind a `const`
constructor.

Purpose: `hotkey_binding.dart:5-8` declares `const HotkeyBinding({required this.modifiers, required
this.key})` over a `final Set<HotkeyModifier> modifiers` with no defensive copy and no unmodifiable
type. AD-9's amended rule mandates that `modifiers` compare as a set and hash unordered to match — and
says nothing about the field being shared. So a reader who implements the rule exactly still gets a
type whose equality can be mutated out from under a consumer, and the value equality is precisely what
then makes a `copyWith` produce an equal state and suppress the rebuild (FLAT-05).

The in-tree precedent is one directory away and even states the price —
`hotkey_grab.dart:17-27` copies on construction and its doc says *"The constructor is therefore not
`const`, which is the price."*

**This edits AD-9's verbatim-frozen constructor at spine lines 239–243**, which needs fresh human
ratification, and the honest position is that **no live defect exists today**: every in-`lib/`
construction passes a fresh set literal, and a `const` set literal is genuinely immutable at runtime.
This is API hardening against a future caller, not a bug fix. The human is told that at the checkpoint
rather than being sold a fix.

Output: a defensive copy, one `const` removed in `lib/`, fifteen removed in `test/`, and a doc that
names the price the way its precedent does.
</objective>
