<objective>
Make the portal handshake honour the packaging decision taken in plan 01-01, and make it impossible
for the settings screen to hang on a portal that never answers.

Purpose: ARCH-02's recorded consequence is that *"because Flatpak is in the set,
`wayland_portal_global_hotkey.dart`'s `Registry.Register` call becomes conditional on the packaging —
a sandboxed build must not register, an unsandboxed one must — so AD-11's step 1 is now a variable in
the sequence rather than a constant"* (DW-89's own `decision:`, ledger line 1349). The portal spec is
blunter than AD-11 is: *"This interface will not work with applications xdg-desktop-portal identifies
as sandboxed."* So inside a Flatpak the call is dead weight at best and an error line on every launch
at worst.

The adapter refuses to detect a sandbox today, and its stated reason is sound:
*"no sandbox detector exists here because the signals one would key off include `/.dockerenv`, which
is true in this project's own container, so a detector would take the sandboxed branch in every test
run"* (`:363-371`). That objection is answerable — `/.flatpak-info` is written by the Flatpak runtime
inside the sandbox and by nothing else, and measured in this container on 2026-09-01: `/.dockerenv`
**exists**, `/.flatpak-info` is **absent**, `$FLATPAK_ID` is **unset**. A predicate over the latter
two does not fire here, which is exactly the property the objection asked for.

D-17 adds the second half: a portal that never answers must fail after a few seconds, leaving the
previous shortcut in effect, so Settings never hangs with no way out.

Output: a pure `PortalAppIdRegime` predicate shaped like `DisplayServer.fromEnvironment`, a
conditional step 1, and a bounded handshake that does not cancel a dialog the user is reading.
</objective>

The whole shape to mirror — `lib/src/infrastructure/hotkey/display_server.dart` (37 lines):
```dart
enum DisplayServer {
  x11,
  wayland;

  static DisplayServer fromEnvironment(Map<String, String> environment) {
    final sessionType = environment['XDG_SESSION_TYPE']?.trim().toLowerCase();
    if (sessionType == 'wayland') { return DisplayServer.wayland; }
    if (sessionType == 'x11')     { return DisplayServer.x11; }
    final waylandDisplay = environment['WAYLAND_DISPLAY']?.trim();
    if (waylandDisplay != null && waylandDisplay.isNotEmpty) { return DisplayServer.wayland; }
    return DisplayServer.x11;
  }
}
```
Enum + static `fromEnvironment(Map<String,String>)`, pure, trimmed inputs, and a doc comment stating
*why the fallback is the fallback*. The new predicate adds one injected
`bool Function(String path) fileExists` so a binding-free test drives both branches with no sandbox.

The bounded-request idiom to reuse —
`lib/src/infrastructure/panel/window_manager_panel_visibility.dart:531-553`:
```dart
  Future<bool> _answered(String call, Future<void> Function() issue) async {
    var answered = true;
    await issue().timeout(
      _requestTimeout,
      onTimeout: () { answered = false; },
    );
    if (!answered) {
      _log(() => _logger.error(
        'the window did not answer $call within ${_requestTimeout.inMilliseconds} ms; '
        'the request was abandoned so the next press is still served',
        context: {'call': call, 'timeout_ms': _requestTimeout.inMilliseconds},
      ));
    }
    return answered;
  }
```
Its doc (`:530-533`) explains the shape: reported through `onTimeout` plus a local flag rather than
by catching a `TimeoutException`, because "a seam is free to have deadlines of its own, and one of
those expiring is the window *refusing* the call, not this policy firing."

The budget to reuse — `lib/main.dart:242`:
`const Duration _unresponsiveCallBudget = Duration(seconds: 5);`
injected at `:114` as `requestTimeout: _unresponsiveCallBudget`. **Do not add a third constant.**
The adapter's existing `_teardownBudget = Duration(seconds: 2)` (`wayland_portal_global_hotkey.dart:1307`)
is teardown-only and stays teardown-only.

The AD-11 sequence, with step 0 new:
```
0. sandboxed?  → the portal derives the app id from sandbox metadata; SKIP step 1 entirely
1. org.freedesktop.host.portal.Registry.Register(app_id)      [unsandboxed only]
2. GlobalShortcuts.CreateSession  → await Response on the Request path
3. GlobalShortcuts.BindShortcuts  → await Response; CHECK the `shortcuts` read-back
4. subscribe Activated + ShortcutsChanged, filtered on session handle and sender
```

**State the reversal in the code, do not perform it silently.** The adapter's own source records that
the bind path has no timeout *by intent*: "AD-11 makes a portal dialog the user must answer normal,
and cancelling one out from under them would be worse than waiting" (`:1300-1307`). D-17 is a
product decision that overrides that engineering judgement and it wins — but the old reason must be
carried into the new rule, or the daemon starts cancelling portal dialogs the user is still reading.
Replace that paragraph; do not leave it contradicting the code beneath it.

**Bound only the steps with no dialog behind them.** The GlobalShortcuts portal shows its dialog on
`BindShortcuts`, not on `CreateSession` — the adapter's own comment near `:470-480` says so. So:
- bound the name-owner lookup, the Register call (unsandboxed path) and `CreateSession`;

Decide which of those two and say which in the code's doc, with the reason. Whichever is chosen, a
`BindShortcuts` that is still waiting must never be cancelled by this policy.

**Abandon the wait; never send a portal `Close` on timeout.** The session is what the user is being
asked about. Abandoning means: stop waiting, return the *previous* outcome to the UI — so the
previous shortcut stays in effect, which is exactly what D-17 asks for — and let a late `Response`
arrive on `bindingChanges` if it eventually comes. Plan 01-08's precedence rule is what makes that
late arrival safe to apply, so the two plans are two halves of one design; note the dependency in the
doc.

**Reuse the existing bounded-request idiom, verbatim in shape.** `_answered(String call,
Future<void> Function() issue)` from the panel adapter: `issue().timeout(budget, onTimeout: …)` with a
local flag, not a caught `TimeoutException`, because a seam expiring its own deadline is the seam
*refusing* the call rather than this policy firing. Copy that distinction into the new helper's doc.
CONTEXT.md is explicit that a second timeout pattern must not be invented.

**Inject the budget; do not define a constant here.** Thread `main.dart`'s existing
`_unresponsiveCallBudget` (5 seconds, `main.dart:242`, injected at `:114`) through
`WaylandPortalGlobalHotkey`'s factory and constructor, exactly as the panel adapter receives it. The
adapter's `_teardownBudget` stays teardown-only and unchanged — it is a different budget for the
opposite reason (a daemon that cannot exit is the worse failure there).

**Where the budget applies:** inside `_callThroughRequest` (`:582-716`), per call, parameterised by
which call is being made — not as one blanket wrapper around `_bind`. A blanket budget is precisely
the anti-pattern Pitfall 4 names.

**Preserve three things that are load-bearing and must not be simplified by this edit:**
1. **Sender filtering.** `_callThroughRequest` matches the Request `Response` on the portal's
   resolved unique name (`:582-640`), and the signal subscriptions filter on sender (`:772-787`).

   `HotkeyBound` before this was added. `Activated` is the entire path from a key press to a panel
   that reads the clipboard.
2. **`Random.secure()` handle tokens**, so the Request object path is not guessable by another bus
   peer. Pinned by `test/architecture/hotkey_confinement_test.dart:150-168`, which fails if `Random()`
   is substituted. Do not touch.
3. **The `_queue`** (`:196-256`). The spec says an application can only attempt to bind shortcuts of
   a session once, so a rebind must close the old session and create a new one — and two interleaved
   rebinds leave an untracked live session on the compositor. Preserve the idiom exactly.

**The read-back check in `_bindShortcut` (`:532-546`) stays.** A portal that discards the bind answers
*successfully* with the shortcut missing from the returned subset, and the code already gets this
right. A timeout must not become a path that skips it.

**`_readResponse` / `_shortcutsIn`'s distinction is load-bearing** (`:1068-1118`): `null` means
unreadable, `{}` means discarded. Do not collapse them.
