<objective>
Build the oracle before the fix, and prove it fails first.

Purpose: G-01-13 was invisible to a 983-row suite for a whole phase, and it was *also* invisible to
the obvious live oracle. The UAT reporter watched `xwininfo`'s Map State across four presses, saw
`IsViewable` every time, and concluded the daemon never acted. It had acted twice per press. The
panel really unmapped and really re-mapped, 8-16 ms apart, and Map State samples neither edge.

So the first deliverable is not the fix. It is an oracle that can *see* this class of defect — a
timestamped X event stream on the daemon's own toplevel — plus a recorded run against the build that
still carries the bug, showing the oracle classifying it as FLICKER. Without that recorded run,
every green result plan 01-12 produces is unfalsifiable.

The harness also has to carry the routes the fix must *not* break. CAP-14's focus-loss hide is
healthy at HEAD (UAT test 14, four routes, re-measured during the diagnosis), and a fix that
suppresses a spurious dismissal is one edit away from suppressing a real one. Those routes are
baselined here so that 01-12's run is a comparison rather than an assertion.

Output: `tool/uat/panel_toggle_probe.sh`, committed, plus a pre-fix baseline for six routes quoted
in this plan's SUMMARY.
</objective>

**The pre-fix event stream, measured.** `xev -id 4194307 -event structure -event focus`, one press
of `Ctrl+Shift+G` held 250 ms at a **mapped** panel:

```
FocusOut  window 0x400003  mode NotifyGrab          detail NotifyVirtual
UnmapNotify window 0x400003
FocusOut  window 0x400003  mode NotifyWhileGrabbed  detail NotifyVirtual
```

Counts: `UnmapNotify: 1  MapNotify: 1`. Map State before and after: `IsViewable`. **That is the
defect, and that is why the counts-and-order oracle catches it while the state oracle does not.**

**Focus ownership per route, measured.** `XGetInputFocus` (what `xdotool getwindowfocus -f` calls):

| Route | Focus before | Focus after | Moved? |
|---|---|---|---|
| daemon's own grab, key held 250 ms, panel mapped | `4194308` | `4194308` | no |
| foreign client's passive grab on `Ctrl+Shift+H` | unchanged | unchanged | no |

| desktop click at `(1400,870)` | `4194308` | `2097439` (openbox; carries no `_NET_WM_PID`) | yes |

The desktop-click route also unmapped the panel at HEAD, confirming UAT test 14: CAP-14's focus-loss
hide is healthy and must stay that way.

**A foreign grabber, for the control route.** A second X client that passive-grabs a combination the
daemon does not own. `python3` + `ctypes` + `libX11.so.6` is enough and is what the diagnosis used:
`XOpenDisplay(NULL)`, `XDefaultRootWindow`, `XStringToKeysym('h')`, `XKeysymToKeycode`, then
`XGrabKey(d, keycode, ControlMask|ShiftMask, root, False, GrabModeAsync, GrabModeAsync)` and
`XSync`, then sleep. `ControlMask` is `1 << 2`, `ShiftMask` is `1 << 0`. Confirmed working on `:99`
on 2026-09-05: it grabs, and firing `Ctrl+Shift+H` delivers `FocusOut mode=NotifyGrab` to whichever
window holds the focus.

**Timestamping.** `xev` prints no wall clock. Pipe it through a line timestamper so the recorded
stream is checkable:
`python3 -u -c "import sys,time"$'\n'"[sys.stdout.write('%.3f %s'%(time.time(),l)) for l in sys.stdin]"`
The **verdicts must not depend on those timestamps** — they are for the record. Verdicts are decided
by counts and order inside a fixed settle window, which is what makes them stable.

Shared scaffolding, in this order:

1. **Preflight.** Assert `DISPLAY` (default `:99`) answers, that `xev`, `xdotool`, `xwininfo`,
   `xprop`, `python3` and `dbus-run-session` are on `PATH`, and that the release bundle exists.
   Any miss is a halt with a named reason on stderr and a non-zero exit — never a route verdict.
2. **Start a daemon in its own XDG tree**, per the recipe in `<interfaces>`. Use a per-run directory
   derived from `mktemp -d` rather than the fixed `/tmp/hgc-run2` in the recipe, so two runs cannot
   read each other's config or lock. Wait for the toplevel to exist rather than sleeping a fixed
   time: poll for up to 30 s, then halt with a reason if it never appears.
3. **Resolve the toplevel.** Search by class `com.divertedriver.HotkeyGrammarCorrector`, keep only
   ids whose `_NET_WM_PID` equals the daemon's pid and for which `xwininfo -id` reports a `Map State`
   line. Require **exactly one** survivor; zero or several is a halt with the candidate list printed.
   Echo the chosen id and its `_NET_WM_PID` so a reader can check the harness watched the right
   window. (Measured: the id is the toplevel, and the window `XGetInputFocus` names is a *child* of
   it — do not require the two to be equal.)
4. **Confirm the daemon owns the grab**, so a route that observes nothing is never mistaken for a
   working daemon: the first press must move the panel. Run the `show` step below once as a warm-up
   and halt if it does not map the window.
5. **Per-press measurement.** Start `xev -id <toplevel> -event structure -event focus` into a
   per-press log, piped through the `python3` timestamper from `<interfaces>`. Give it 500 ms to
   attach. Record `xdotool getwindowfocus -f` as FOCUS_BEFORE. Fire the press with
   `xdotool key --clearmodifiers ctrl+shift+g`. Wait a fixed 1000 ms settle window — 60x the
   measured 8-16 ms flicker, so it is a margin rather than a threshold. Record
   `xdotool getwindowfocus -f` as FOCUS_AFTER. Stop `xev`.
6. **Classify** from the log, using counts and order only: `UnmapNotify` count, `MapNotify` count,
   and the order of the first of each. Verdicts: `MAP=1 UNMAP=0` is SHOW; `UNMAP=1 MAP=0` is HIDE;
   `UNMAP>=1 MAP>=1` with an unmap first is FLICKER; both zero is NOTHING; anything else is
   UNCLASSIFIED and prints the raw stream.
7. **Emit one result line per route**, greppable and stable:
   `ROUTE <name> UNMAP=<n> MAP=<n> FIRST=<Unmap|Map|none> FOCUS_BEFORE=<id> FOCUS_AFTER=<id> WINDOW=<w> VERDICT=<v>`
   followed by the timestamped stream indented under it. `WINDOW` names the slice of
   the stream the verdict was computed from and is `all` for every route in this plan.
   It is emitted from the start, and by every route, because plan 01-13 adds two routes
   that must classify from events after a specific moment rather than from the whole
   press — and a result-line format that changes halfway through the set would silently
   invalidate the baseline this plan records. Counts and `FIRST` are always computed
   over the same slice `WINDOW` names, never over a different one.
   Fields are separated by exactly one space and appear in the order shown. Both the
   gates here and 01-13's match on adjacent field pairs, so an extra separator or a
   reordered field fails them.
8. **Always stop the daemon and the grabber** on exit, including on halt, via a `trap ... EXIT` that
   kills by the bracketed pattern from `<interfaces>` and removes the temp tree.

The `hide` route itself: bring the panel up (one press, expect SHOW), then measure one further press
at the now-visible panel. Against the current bundle this second press is the defect, and the
harness must call it FLICKER.

Do not add any tolerance, retry or "if it looks like it hid, call it hidden" smoothing. The whole
value of this file is that it reports what happened.
