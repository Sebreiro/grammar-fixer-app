# Fix KDE Wayland panel raising from tray and hotkey

Implemented both entry routes with the user's existing toggle/session behavior. Portal activation tokens are preserved after sender/session/shortcut validation, captured at show intent before queued native calls, and supplied to the pre-created GTK window's presentation. KDE's missing tray token method is handled on the pinned Ayatana library's shared session connection; token receipt stores permission without raising anything. Presentation consumes either the current tray token or the request's portal token, with one-use semantics.

The domain interfaces and provider/history/config contracts are unchanged. No new window on hotkey press, always-on-top policy, provider fallback, or restart behavior was added. The composition root injects activation context and the GTK presenter, while window_manager still reports actual window events. Native initialization is completed during startup, with the existing bounded platform-call budget.
