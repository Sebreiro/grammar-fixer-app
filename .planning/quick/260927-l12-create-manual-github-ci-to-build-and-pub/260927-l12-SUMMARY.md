# Quick 260927-l12: Manual Linux Release Summary

Implemented a manual GitHub release workflow that tests and packages one Linux Flutter build into a tarball, `.deb`, AppImage, and Flatpak before pushing a version tag or publishing assets. The first real four-format runner build and GitHub publication remain unobserved.

## Accomplishments

- Added a single packaging entry point and a verifier for four versioned artifacts, the full Flutter bundle, desktop integration, sidecar assets, pinned SDK import, bundled CLI, native libraries, and Flatpak sandbox permissions.
- A fresh installed config selects the packaged `sidecar-python` wrapper beside the executable; development checkout and user-configured paths remain available.
- Added a pure version planner for stable bumps, branch slugs and sequences, and exact-tag retry; the release runner checks source provenance, uses an atomic stable ref push, and compares draft and published assets by name, size, and SHA-256 digest. It uploads verified packages before tagging and binds their manifest, run ID, and attempt to the tag for recovery.
- Packaged tarball and AppImage desktop installers, an AppImage launcher that keeps sidecar paths stable and loads bundled native libraries, and the Flatpak tray libraries absent from GNOME 50.
- Included the vendored Flatpak tray libraries' package copyright notices alongside their binaries.
- Documented manual and recovery dispatches, local packaging commands, install paths, Python requirements, repository rules, and Wayland verification limits.

## Deviations from Plan

- Used `uv` when system Python lacked `pip`, and added it to the CI toolchain. The runtime SDK wheel selection targets Flatpak's Python version separately from the host package version.
- Added `tool/run_linux_release.sh` and `tool/release_plan.dart` so publication logic remains reviewable and AGENTS.md's one-public-type-per-file rule holds.
- Replaced rebuild-based retry with retrieval of the original 90-day retained package artifact after code review showed independent builds could change hashes. A tag binds the artifact by run ID, attempt, and SHA-256 manifest.
- If an external actor wins a branch tag race after packages are preserved, publication fails closed. Rerunning the manual workflow selects the next sequence and rebuilds before a new artifact is preserved; changing the version inside the publish step would invalidate the stored package names and hashes. Workflow-owned runs already share one queued concurrency group.
- Tightened release API error handling and Flatpak permission comparison after implementation review; committed as `d46f933` and `6e0eee1`.
