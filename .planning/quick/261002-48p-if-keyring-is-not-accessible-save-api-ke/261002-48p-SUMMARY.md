# API key config fallback completed

An entered key first goes to Secret Service. If that write is inaccessible or fails, an infrastructure ProviderKeyWriter decorator saves the trimmed key in `providers.openai-compatible.settings.apiKey` through ConfigStore. The fallback preserves provider settings, presets, and hotkeys, re-derives after bounded config conflicts, and reports failure if config cannot commit.

Removed JsonConfigStore's obsolete policy that stripped new key values. Existing atomic replacement, private scratch files, and owner-only final permissions remain in use. SettingsController applies a successful fallback config to the daemon immediately; the existing resolver continues to prefer keyring, environment, then config.

Settings explains fallback, uses destination-neutral success feedback, and retains its source label/plaintext config notice. Only successful persistence clears the masked draft; failure in both destinations remains retryable.
